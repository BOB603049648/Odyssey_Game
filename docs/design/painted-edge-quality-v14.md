# 场景边缘与素材质量 · 第十四轮

本轮集中修整雾岸、经堂的前景素材，并改善所有 Three.js 场景的缩小采样。没有更换场景主题、故事、解谜、行走、存档或角色动画。

## 素材

使用 OpenAI 图片生成模型，依据原场景绘画和旧透明选择图重新修整轮廓、木雕、瓦片、石刻、草叶与器物。最终接入 7 张 RGBA 素材：雾岸前景图、经堂前景图，以及独立门楼、石刻、泉眼、取走水瓢的泉眼、路石组合。为避免相邻物件粘连，门楼、石刻和泉眼等使用独立透明图。保留现有构图、归一化位置和物件地面交互锚点。模型原始 PNG、来源记录保存在 `docs/assets/spatial-v14/`；完整生成原件也保留在工作区 `generated_images/`。

透明图片预览中的空白须按 alpha 合成查看；不可把隐藏 RGB 当作可见边缘。已在深浅底色上检查实际 RGBA 合成，检查图是素材诊断图，不是游戏截图。

打包阶段仅复制、裁掉透明空白、无损编码 WebP，没有用程序重绘或模糊画面。逐张验证编码后 alpha 和所有可见 RGBA 与生成源图对应区域一致。裁边矩形记录在 `src/assets/art/spatial/refined/regions.json`，通过纹理矩阵还原其在原画上的 UV 位置。

## 几何与渲染

- 新素材的 RGB、透明轮廓、投影共用同一张图。取消“原场景 RGB + 另一张生成图 alpha”的错位组合。
- 雾岸完整门楼替代原来的屋顶和两根立柱分块，消除截断雕花、屋檐和接缝；底部仍有立体支撑。
- 经堂两侧立柱、花草、门槛组成连续前景框，框内家具以几何孔洞排除，并继续独立遮挡、交互。
- 岩石、浮木、泉眼等外框留透明余量，轮廓由素材 alpha 决定。泉眼两状态都有对应 RGBA 颜色与阴影。
- 前景最下缘略穿过地面，避免整块前景底边悬空的接缝。交互落脚点保持原值。
- 透明素材上传时预乘 alpha；滤波后先还原 RGB，再做 sRGB 解码，防止透明空白内的颜色进入轮廓。场景纹理启用 mipmap，最多 4 倍各向异性过滤；行走等动画图集仍不启用 mipmap，避免相邻动画帧串色。
- 后期场景使用最多 4 个 MSAA 采样；不经过后期的场景，其离屏转场目标也启用抗锯齿。设备只支持 2 或 0 时按能力降级，不在已做后期的目标上重复 MSAA。

## 体积与验证

新前景运行素材合计 1,581,748 字节，替代的两张旧 alpha 图合计 1,163,940 字节，增加约 408 KiB；不在标题启动阶段下载整套场景。裁边后共 3,555,237 个纹理像素，避免每个独立物件都上传完整画布。标题启动 JS gzip 口径与上版基本相同（本地测量减少 1 字节），不代表用户网络加载耗时已测量。

88 项检查、16 个测试文件和 TypeScript/Vite 生产构建通过。覆盖裁边 UV 注册、前景与地面接触、材质与投影一致、泉眼状态切换、动画采样隔离、相机投影、两个场景可达性、热点交互和场景切换。

另用实际 Three.js 导出的几何，在 Blender 中检查了雾岸、经堂的初始与斜视结构，并据此修正底缘接触。离线渲染不包含浏览器 UI、Three.js 后期或同样的采样器，因此不能替代游戏实际画面验收。本轮仍缺少受支持的浏览器控制工具，未完成浏览器实机、手机帧率与 WebGL 像素级验收，不把旧截图或离线结构图当作新版游戏截图。
