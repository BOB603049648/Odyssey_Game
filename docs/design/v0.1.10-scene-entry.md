# v0.1.10：切场景后交还操作

## 问题与行为

原来换场景会给 `.traveler-bob` 增加固定 880 ms 的平移动画，横向 42 px、纵向 28 px，与实际落脚位置和玩家输入无关。长按方向键时，虽然过门清空了已按键集合，系统随后发来的重复 `keydown` 又会把方向加回；触屏摇杆也可能保留旧手指的捕获与原点。这会造成进场后仍被带着走的感受。

现在跨过门线时结束旧路线、速度、动作移动状态和按键／摇杆指令，进入目标场景后在已有安全落点站定，保留过门方向的朝向。删除角色入场平移及其定时器。镜头在场景切换的同次渲染中设置到新落点，避免慢加载时留下旧镜头位置。

移动由第一次按键建立，持续按住由游戏循环处理；OS 重复事件不再创建移动意图。新场景的摇杆拥有新的手势状态，旧手指继续拖动不能恢复旧指令。场景准备好后，松开重按、点新的地面位置或重新触摸摇杆即可接管，不设置额外等待时间，也不等待背景淡化结束。加载期间的输入不排队补走。

路线选择仍表示走向指定出口，玩家可在途中改向；实际走过门线后才换场景。此修复针对切换后的非主动移动，不改变地图、门线和主线进度。

## 验收

本地全量测试为 119 个文件、843 项测试，生产构建通过。独立浏览器专项覆盖桌面、自动路线、慢加载和手机触摸。相同的重复按键操作在 v0.1.9 发布包中可复现：进入棚火后，无新的按键起始，角色仍从 x=.34 走到约 .375；本版在相同操作下保持落点不变。新按键／新触摸在专项中约 87–272 ms 内产生可测位移（包含浏览器调度与加速到 .004 世界坐标位移的时间）。

- `sceneEntryProduction.test.tsx` 使用真实生产移动循环，验证跨门后重复按键失效、新按键立即移动、路线到达即止、旧触摸手势退休、加载期间按键不排队，以及新场景第一帧的镜头位置。
- `npm run test:scene-entry` 使用 Chromium 的实际键盘／触摸输入，检查不操作时世界坐标固定、没有 CSS 入场平移、手机摇杆回中、冷加载恢复和新指令响应。保存采样、截图和视频。
- `npm run test:wayfinding` 复验桌面和手机的十条场景连接、路线中断、拒绝非法地面、手动过门与旋屏。

存档格式兼容。部署后通过 `/test/version.json` 核对版本 `0.1.10` 和实际提交，避免仍在测试旧版。
