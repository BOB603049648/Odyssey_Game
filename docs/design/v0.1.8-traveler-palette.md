# v0.1.8：待机与动作服装配色

## 问题

待机图和后来生成的动作图集来自不同绘制批次。待机服装偏冷蓝黑，行走／交互服装偏灰、偏亮。原代码没有按素材区分明度的 CSS 滤镜，色差已经存在于原图，单纯调整整个人物亮度会同时改变脸、头发和皮具。

浏览器从前／侧／背三个待机图的衣服中间色采样，sRGB 加权亮度中位数分别约 31.2、38.9、29.6（0–255）。12 个行走格同类采样为 64.1–77.4，修复后为 34.1–40.4；每格与对应待机的差距缩小至少约 77%。这是固定采样区域的比较，不表示所有姿势、材质和光照应当具有完全相同的像素。

## 校准方式

- `TravelerPalette.tsx` 提供 sRGB SVG 材质滤镜，以红／蓝的相对关系区分暖色材质与中性、冷色服装，并让高光逐渐退出校准。服装暗部统一匹配蓝黑色参考。
- 只在图集裁剪容器上应用。待机原图、脸部与金发／棕色皮具的暖色范围不整体压暗；场景自己的光照仍正常作用于整个人物。
- 用互补遮罩分别合成校准部分和原始部分，再相加，保留原有 alpha。三份图集的浏览器逐像素检查中，透明通道最大差值为 0，选定暖色区域的 RGB 最大差值为 0。
- 每个主角只持有一个稳定滤镜定义。滤镜依据实际显示的图集判断，冷加载暂留的待机和淡出帧保留自己的配色，不随下一帧的动作状态误切换。
- 原始图片、裁剪坐标、透明度蒙版、脚底注册、动画帧数和播放速度不变，也没有新增贴图下载或逐帧 Canvas 重编码。

## 验收

`CHROMIUM_PATH=/usr/bin/chromium npm run test:palette` 检查三份图集的 32 个格、暖色材质、透明通道以及真实游戏中四朝向起步／停步的当前帧与淡出帧。截图和测量保存于 `artifacts/traveler-palette/`。单位测试检查旧待机暂留、图集同节点换帧、交互淡出和多主角滤镜身份。

移动和动作回归继续使用 `npm run test:movement`、`npm run test:performance`，验证单图集加载、裁剪尺寸、短按停步、喝水、坐下／起身、暂停及移动打断。已有源图指纹与接地像素检查保持有效。

这是现有素材的配色统一，不增加步行动画帧数，也不重绘服装轮廓。后续更换动作素材时应复核滤镜，避免对已经统一配色的新素材重复校准。
