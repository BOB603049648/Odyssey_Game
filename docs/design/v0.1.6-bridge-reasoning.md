# v0.1.6 雾径：从辨认刻符到表达决定

## 玩家经历

此前学会「危险」后点击「停下」，立即完成避险。现在玩家需要观察证据、理解新的刻痕、向同行者表达打算，再一起退回稳固地面。

1. 从前坪沿真实路口走进雾径，在木牌或桥板旁打开近景。观察开裂的桥板支架与磨断的扶绳；两处观察记录独立保存。近景依据原场景绘制，放大远景中不容易看清的边缘磨损，不改变场景布局与行走地面。
2. 看过两处细节、理解「危险」后，可以在木牌旁辨认「等待」。玩家观察向导停在路口的行为，从三幅情景中判断意思；错选可改，只有正确辨认才把该字收入词库。这是一处情境学习入口，不要求先刷完整个抽象层，也不替玩家解锁整层。
3. 用已学刻符组成「眼前的状况／接下来的打算」。槽位和刻符均可改选、清空，选过的刻符可以展开回忆情景。未知刻符不会作为可用答案出现，中文教学义仍由原有开关控制。
4. 明确点「向同行者示意」才提交。危险＋等待、危险＋保护都能成立，后者需实际学过保护。错误的状况会得到指向桥板证据的反馈；错误的打算会让向导继续留在原地。不消耗道具、不重置观察、不强迫死亡重开。
5. 同行者理解后，近景收起，它先望向来路，再沿原有动作系统退到左侧路口内侧。玩家仍可改向、查看菜单或重新观察；需要实际穿过返回前坪的门线，避险经历才完成。只是学字、示意、关闭近景或提前离开，都不能替代这一步。

主线其他经历保持原有操作。按推荐路线，原先石壁的 18 字加上桥边实际学到的等待，共 19 字完成首章；保护等其他词仍可提前自由学习。28 字全收集和复用保持可用。

## 状态与恢复

观察、两个槽位及是否已经示意，保存为 `dba.puzzle.bridge.*` 标记。未完成的记录可以离开再回来，也可刷新、备份、恢复。阶段从这些标记与已学知识派生；无效类型或未知刻符不会成为有效的约定。

`bridge-act` 只在雾径探索且未打开存档／词库等菜单时接受。完成经历的唯一新入口是：在有效约定之后，从雾径返回前坪。旧版本已经拥有 `dba.beat.danger` 的存档直接视为完成，不强制重做，也不会自动补发等待字或学习奖励。

近景暂停移动和自动帮助，支持键盘焦点限制、Esc 关闭和触屏操作。固定标题保留关闭入口；手机可滚动，横屏采用并排布局。近景图片失败时保留观察按钮与文字反馈，可手动重载图片。情景学习图沿用原有文字回退。

## 声画反馈

- 新增一张 1536×1024 桥边近景，运行时 WebP 约 407 KiB；原图、生成说明和转换参数保存在 `docs/assets/bridge/`。
- 两处观察复用已有木头吱响；选刻符、错误理解、本地学字、同行者回应与最终经历完成使用现有声音系统。恢复存档不重播获得奖励。
- 向导从 P0 等候点转到 P1 返回点，沿用先观察、再移动、最后落地的动画及暂停机制。旅人的步态仍是现有三方向四帧，本轮没有加入八帧走停或转身素材。

## 验收

- 核心：两处观察的必要性、错误理解、局部学习、组合修正、两种有效打算、实际返回完成、无效调用、存档往返与旧完成存档。
- 声音：观察吱响、学字短音、回应猫叫、返回奖励分别由实际状态变化触发。
- 界面：图片失败和重试、未知词不暴露、选择不自动提交、显式示意、旧存档的只读结果。
- 浏览器 `npm run test:bridge`：桌面和 390×844 触屏尺寸实走进出雾径；近景后面的移动冻结，阅读不冒自动提示；错误读字／组合可改，刷新恢复；向导有实际位移而非瞬移；手机旋屏与故障图片重试。
- 浏览器 `npm run test:learning`：从新存档走完取水、休息、分食、新雾径谜题、19 字离岛和首章回忆，再刷新继续。
- `test:browser` 和 `test:gameplay` 同步采用新流程，保留 28 字、可选线索及原有首章检查。

## 后续

下一项优先制作旅人走停、反向和转身的连续过渡，再做可取消的走近交互。谜题后续可继续探索不同刻符组合带来不同可恢复反应；本轮先以一段完整、能保存和复验的雾径经历验证这个方向。
