# v0.1.9：行走中间姿势与节奏

旧行走每个视角只有 4 帧，在参考尺寸、全速移动时每秒约更新 6 次姿势。腿部跨度偏大，缺少过腿过程；只缩短 CSS 淡入淡出无法补出姿势。

## 改动

前、侧、背三个视角各改为 8 个姿势，左向镜像侧向。重新生成完整人物，补充抬脚、过腿和伸脚过程，检查相反半周期的腿部交替。每格保持同一像素尺度，统一裁剪框，脚底注册独立测量，不再把裁剪框底边当作鞋底。图集内各方向的身体高度差小于 8 个源像素，约为显示高度的 1.8%。

参考步频由 1.5 改为 1.65 个循环／秒，姿势更新从约 6 次／秒变为 13.2 次／秒，即约 76 ms 一帧。实际帧率还受行走速度、透视和场景人物尺寸影响；慢推摇杆仍按实际位移推进，不用独立计时器制造滑步。正常步态淡出缩短为 28 ms，起停／转向保留 110 ms。

左右落脚相位改为第 1、5 帧。跳过显示帧时取跨过的最近一个接触点，只发出一次声音；保留 150 ms 最小间隔、短有效期和停步销毁，避免卡顿后爆发补播。喝水、坐下等动作帧不变。

## 资源与配色

24 格共用一张 3072×1536 WebP（710,028 字节）；旧图集为 965,138 字节。增加姿势的同时下载体积减少约 26%，不增加转向请求。旧图留作制作参考，但排除在运行资源映射之外。

PNG 原图和来源记录保存在 `docs/assets/traveler-walk8/`。打包只排列完整源格，再以 WebP quality 92 编码；alpha 完全保留，RGB 采用有损压缩，不将其宣称为无损图片。沿用 v0.1.8 的服装材质遮罩，为较亮的新行走图单独设置 RGB 系数 .40/.46/.56，原交互图保持 .47/.53/.64。按实际显示图选择配置，暖色材质与透明边缘保持；两个滤镜定义都固定复用。

## 验收

本地全量检查通过 118 个测试文件、839 项测试，生产构建通过。新行走格校准后服装采样亮度为 34.0–39.0（0–255），前／侧／背待机参考分别约 31.2／38.9／29.6；每格亮度差均小于 9。浏览器逐像素验证的暖色 RGB 和 alpha 最大差值均为 0。这个比较验证材质一致性，不要求不同姿势的像素完全相同。

- 单元测试检查全速步态的最大姿势停留时间、真实位移驱动、24 格单次解码、漏帧落脚音、固定裁剪与暂停／停步。
- `travelerWalkPixels.test.ts` 从原图与实际运行 WebP 逐像素检查 alpha、透明边界、压缩误差、脚底注册和身体高度，防止混入不透明背景或某帧突然变大。
- `npm run test:movement` 在真实游戏中从新存档进入海岸，以键盘操作四个朝向，检查全部 8 帧、冷加载、停止距离、原地停步与固定图像缩放，录制视频并保存截图。
- `npm run test:palette` 检查 44 个行走／动作格的服装亮度、暖色材质与 alpha，再检查游戏中的起停过渡。
- `npm run test:performance` 和 `npm run test:foley` 检查交互、暂停／打断、三种地面的脚步声和实际混音输出。

这是 8 帧精灵动画的改善，仍有离散绘制的边界，不等同于骨骼动画或每秒 60 张独立姿势。服务器需部署本版后才能看到变化；存档兼容，主线与移动速度不变。
